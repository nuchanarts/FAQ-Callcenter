# Admin Screen Constitution Checklist: Self-Service FAQ MVP

**Purpose**: Release-gate review of the requirements for the admin content screen (`/admin`, "จัดการเนื้อหา" — topic list, filters, status, edit/hide/restore/delete) against constitution v2.0.0 Principles I–XV. Tests whether the requirements are complete, clear, consistent and measurable — not whether the code works.
**Created**: 2026-11-16
**Feature**: [spec.md](../spec.md) · [plan.md](../plan.md) · [data-model.md](../data-model.md) · [contracts/interfaces.md](../contracts/interfaces.md) · [constitution](../../../.specify/memory/constitution.md)
**Audience / timing**: Reviewer or Call Center team lead, before go-live (formal gate)

**Note**: This custom checklist is generated by the `/speckit-checklist` command based on feature context and requirements.
**Review Ownership**: This checklist is a reviewer-owned requirements-quality review artifact. Mark an item `[x]` only when the reviewer determines the requirements-quality criterion is satisfied.
**Marker Semantics**: `[x]` means the criterion has been reviewed and satisfied for requirements quality. It does not mean implementation work is complete.

## Self-Service & Content Standards (Principles I, II, IV)

- [ ] CHK001 - Do the topic-form requirements make the level badge (ทำเองได้ / ทำเองได้บางส่วน / ต้องแจ้งทีม) mandatory, with guidance on how an admin chooses the correct level? [Completeness, Spec §FR-016, Constitution I]
- [ ] CHK002 - Is it specified that every solution must contain numbered steps and a "> ถ้ายังไม่ได้" note box, or is that standard left to admin discretion? [Gap, Constitution Content Standards]
- [ ] CHK003 - Is the rule "title starts with the symptom the user sees, not the cause" captured as a requirement or form guidance for admins? [Gap, Constitution IV]
- [ ] CHK004 - Are requirements defined for linking admin edits to case-report evidence (e.g., source period, case count) so content is traceable to Principle II? [Gap, Constitution II]
- [ ] CHK005 - Is the weekly "≥ 5 repeated cases → add a topic" and the "update within 2 working days" workflow reflected in any admin requirement or explicitly declared out of scope? [Gap, Constitution Workflow]
- [ ] CHK006 - Are menu-path formatting requirements (`Setting › …`) and the allowed content markup defined unambiguously for admins? [Clarity, Spec §FR-005, Data Model §Content format]
- [ ] CHK007 - Is "keywords" quantified (max count, max length, de-duplication rule) consistently across spec and data model? [Consistency, Spec §FR-016, Data Model §TopicContent]

## Permissions & Reversibility (Principle VI)

- [ ] CHK008 - Are the capabilities of Owner vs Editor roles explicitly specified, or is "same permissions in MVP" documented as a deliberate decision? [Clarity, Spec §Key Entities, Constitution VI]
- [ ] CHK009 - Is it unambiguous which actions are allowed on built-in vs custom topics (edit, hide, restore, delete) for every combination? [Completeness, Spec §FR-013–FR-015]
- [ ] CHK010 - Is "restore original" defined for a built-in topic that is both edited and hidden (does restore also un-hide)? [Edge Case, Spec §FR-014]
- [ ] CHK011 - Are confirmation requirements consistent across destructive actions (restore = 1 confirmation, delete custom = 2 confirmations, hide = none) and is the rationale stated? [Consistency, Spec §FR-014, §FR-015, Constitution VI]
- [ ] CHK012 - Is the behaviour defined when a built-in topic's original changes in a new release while an override exists (which version admins and viewers see, and how admins learn of it)? [Coverage, Spec §Edge Cases]
- [ ] CHK013 - Are audit requirements (who changed what, when) specified beyond "last editor and time", e.g., change history or previous-version recovery for custom topics? [Gap, Spec §FR-018, Assumptions]

## Security & Privacy (Principle V)

- [ ] CHK014 - Are server-side authorization requirements stated for every admin action and page, not only for UI visibility? [Completeness, Spec §FR-012]
- [ ] CHK015 - Are session lifetime, sign-out, and revocation (removed admin loses access) requirements specified with measurable values? [Clarity, Gap, Spec §FR-012, Research §R4]
- [ ] CHK016 - Is the requirement that admin-entered content is always escaped stated for every place admin text appears (viewer card, admin list, admin preview)? [Coverage, Spec §US3 AS-8, Constitution V]
- [ ] CHK017 - Is the https-only link rule specified for both attachment URLs and inline `[text](url)` links in the solution? [Consistency, Spec §FR-006, §FR-016, Constitution V]
- [ ] CHK018 - Do requirements prohibit patient identifiers, tokens and passwords in admin content, and is any detection, warning or review step defined? [Gap, Constitution V]
- [ ] CHK019 - Are sign-in failure requirements defined (generic message, rate limiting / lockout after repeated failures)? [Gap, Spec §FR-012]
- [ ] CHK020 - Are production admin-account provisioning and default-credential restrictions documented as requirements? [Completeness, Spec §Assumptions, Research §R13]

## Data Integrity & Concurrency (Principles VI, XIV)

- [ ] CHK021 - Is conflict detection (FR-017) specified for every write — save, hide/show, restore and delete — not only for save? [Coverage, Spec §FR-017]
- [ ] CHK022 - Is the user-facing recovery path after a conflict defined (message text, reload behaviour, whether the admin's unsaved input is preserved)? [Clarity, Spec §US3 AS-9]
- [ ] CHK023 - Is "saving = publishing" stated clearly enough that admins understand there is no draft or preview-to-viewers stage? [Clarity, Spec §Assumptions, Constitution Workflow 4]
- [ ] CHK024 - Are requirements defined for admin actions while the content store is unavailable (error message, no partial save)? [Exception Flow, Gap, Spec §FR-019]

## Admin List, Filters & UX Consistency (Principles VII, X)

- [ ] CHK025 - Are the admin list's statuses (ต้นฉบับ / แก้ไขแล้ว / เพิ่มเอง / ซ่อน) defined as mutually exclusive or combinable, and how combinations display? [Clarity, Spec §FR-018]
- [ ] CHK026 - Is the admin list's search defined to use the same matching and ranking rules as viewer search, or are differences intentional and documented? [Consistency, Spec §FR-002, §FR-018]
- [ ] CHK027 - Are sort order and paging/virtualization requirements specified for the admin list (Constitution XI requires paging above 50 items)? [Gap, Spec §FR-018, Constitution XI]
- [ ] CHK028 - Are loading, empty (no topics / no filter matches), error and success states specified for the admin list and form? [Completeness, Spec §FR-022]
- [ ] CHK029 - Are admin screens covered by the 360 px requirement, and is acceptable behaviour for the wide topic table on phones specified (horizontal table scroll vs stacked rows)? [Clarity, Spec §FR-021, Constitution VII]
- [ ] CHK030 - Are keyboard-operability and focus requirements defined for admin dialogs (initial focus, Esc, focus return)? [Coverage, Spec §FR-021, Constitution X]
- [ ] CHK031 - Is the live preview requirement for the topic form specified (what it shows, that it matches the viewer rendering exactly)? [Gap, Constitution X]
- [ ] CHK032 - Is an unsaved-changes warning required when leaving the topic form? [Gap, Constitution X "input never lost"]
- [ ] CHK033 - Are all admin UI strings required to come from the centralized Thai strings source, including validation and error messages? [Consistency, Constitution IV, X]

## Performance & Acceptance Criteria (Principles IX, XI)

- [ ] CHK034 - Can SC-004 ("edit and publish in under 2 minutes") be objectively measured — is the starting point, task and user profile defined? [Measurability, Spec §SC-004]
- [ ] CHK035 - Are performance budgets defined for admin pages and actions (list load, save round-trip), or do the constitution's generic budgets explicitly apply? [Gap, Constitution XI]
- [ ] CHK036 - Does each admin acceptance scenario (US3 AS-1…AS-9) map to a measurable, automatable check as required by SC-007 and Principle IX? [Traceability, Spec §SC-005, §SC-007]

## Dependencies, Assumptions & Ambiguities

- [ ] CHK037 - Is the assumption "admin accounts are provisioned by the system owner" paired with a documented process (who, how, offboarding)? [Assumption, Spec §Assumptions]
- [ ] CHK038 - Is the deferral of direct file uploads (≤ 20 MB) reconciled with the constitution's "ลบไฟล์ requires two confirmations" rule, so no requirement is silently dropped? [Conflict, Spec §Clarifications, Constitution VI, VII]
- [ ] CHK039 - Is the production data store dependency (Supabase schema, RLS, service role usage) captured as requirements rather than only in the plan? [Dependency, Plan §Technical Context, Data Model §Supabase mapping]
- [ ] CHK040 - Is the term "admin" used consistently with "Owner / Editor" (constitution) and "ผู้ดูแลเนื้อหา" (UI) across spec, plan and UI text? [Consistency, Terminology]
