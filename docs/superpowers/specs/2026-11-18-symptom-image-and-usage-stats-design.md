# รูปอาการ + สถิติการใช้งาน — Design

วันที่: 2026-11-18 · สาขา: `001-faq-callcenter-mvp`

## ทำไม

1. **รูปอาการ** — ผู้ใช้จำ "หน้าจอที่เจอ" ได้ดีกว่าชื่อ error ถ้ารายการผลค้นหามีภาพหน้าจออาการ
   ผู้ใช้จะเลือกหัวข้อถูกตั้งแต่ยังไม่เปิด
2. **สถิติ** — เจ้าหน้าที่อยากรู้ว่าหัวข้อไหนถูกเปิดดู / ถูกแจ้งปัญหามากที่สุด และให้**ผู้ใช้ทั่วไปเห็น
   ยอดด้วย** เพื่อกระตุ้นให้ลองทำตามหัวข้อยอดนิยมเองก่อนแจ้งทีม

## เป้าหมาย / ไม่ใช่เป้าหมาย / ห้ามเกิด

- เป้าหมาย: แนบรูปอาการ 1 รูปต่อหัวข้อ, เห็นรูปย่อในผลค้นหา; นับยอดดูต่อหัวข้อ ยอดแจ้งปัญหาต่อหัวข้อ
  และจำนวนการเข้าเว็บ; ผู้ใช้เห็นยอดดู + ป้าย "ยอดนิยม" + แถบ "ปัญหาที่พบบ่อย"; เจ้าหน้าที่มีหน้าสถิติ
- ไม่ใช่เป้าหมาย: ติดตามรายบุคคล, กราฟ, ส่งออกไฟล์, กันการปั่นยอดแบบเข้มงวด
- ห้ามเกิด: การนับ/อ่านสถิติล้มแล้วทำให้หน้าเว็บหรือการแจ้งปัญหาใช้ไม่ได้;
  แสดง**ยอดแจ้งปัญหา**ต่อผู้ใช้ทั่วไป (อาจทำให้ข้ามไปแจ้งทีมแทนที่จะลองทำเอง — ผู้ใช้เลือกแล้ว);
  เก็บข้อมูลส่วนบุคคลในตัวนับ

## ทางเลือก (เลือกแล้ว)

- ที่เก็บตัวนับ: **ฐานข้อมูลของแอป** (ผู้ใช้เลือก) — เพิ่มตัวนับใน repository เดิม
  ใช้ได้ทุก backend (file / memory / supabase / sheets) ตัวเลขขึ้นเร็ว ไม่ขึ้นกับ Sheet log
  - ไม่เลือก: อ่านยอดจาก Sheet log เดิม — ช้า ~5 นาที, ไม่มีตัวเลขถ้า Sheet ไม่ได้ตั้งค่า, ช้าลงเมื่อแถวเยอะ
- สิ่งที่ผู้ใช้ทั่วไปเห็น: **ยอดดู + ป้ายยอดนิยม** (ผู้ใช้เลือก) — ไม่แสดงยอดแจ้งปัญหา
- จำนวนรูปอาการ: **1 รูป** (ผู้ใช้เลือก)

## ส่วนที่ 1 — รูปอาการ

**ข้อมูล:** `TopicContent` เพิ่มฟิลด์ `symptomImage: { url: string; caption: string } | null`
(zod `.nullable().default(null)` → ข้อมูลเก่าที่ไม่มีฟิลด์นี้ใช้ได้ทันที) url ต้องเป็น https,
caption ไม่บังคับ ยาวไม่เกิน 80 ตัวอักษร เก็บแยกจาก `attachments` (รูปของวิธีแก้ยังอยู่ที่เดิม)

**ฝั่งเจ้าหน้าที่ (`topic-form.tsx`):** ใต้ช่อง "คำถาม / อาการ" มีปุ่ม "แนบรูปอาการ" ใช้ flow
อัปโหลดเดิม (`/api/upload` → Vercel Blob, PNG/JPG/WebP/GIF ≤ 5 MB) แสดงเมื่อ `imagesEnabled`
เท่านั้น — เมื่อมีรูปแล้วเห็นรูปย่อ + ช่องคำบรรยาย + ปุ่ม "เอารูปออก"/"เปลี่ยนรูป" และพรีวิวด้านขวา
แสดงรูปอาการด้วย ส่วนนี้ร่วม flow อนุมัติ draft เหมือนฟิลด์อื่น

**ฝั่งผู้ใช้:**
- `TopicCard` (รายการ/ผลค้นหา): รูปย่อ ~64×48 px `object-cover` มุมมน อยู่ซ้ายของชื่อหัวข้อ
  `loading="lazy"`, `alt=""` (ชื่อหัวข้ออยู่ข้างๆ แล้ว)
- เมื่อเปิดหัวข้อ (accordion และ AnswerPane): ส่วน "หน้าจอที่พบ" แสดงรูปเต็มความกว้าง (สูงไม่เกิน 20rem,
  `object-contain`) ใต้ชื่อหัวข้อ ก่อนวิธีแก้ คลิกเปิดรูปเต็มในแท็บใหม่ มีคำบรรยายถ้ามี
  alt = คำบรรยาย หรือชื่อหัวข้อถ้าไม่มี

## ส่วนที่ 2 — สถิติการใช้งาน

**สิ่งที่นับ (ทั้งหมดผ่าน `/api/log` เดิม, ตรวจที่ server):**
- `view` — เปิดดูหัวข้อ, 1 ครั้งต่อหัวข้อต่อการเข้าหน้า (dedupe ฝั่ง browser เดิม)
  **แก้บั๊กไปด้วย:** ตอนนี้นับเฉพาะจอกว้าง (`onSelect`) — accordion บนมือถือ/จอแคบไม่ถูกนับ
- `report` — กดคัดลอก/เปิด LINE ในหน้าแจ้งปัญหา; เพิ่ม `topicId` (ไม่บังคับ) เมื่อมาจากหัวข้อ
  (`/report?topic=…`) เพื่อนับยอดแจ้งต่อหัวข้อ ส่วนแถวใน Sheet log เพิ่มคอลัมน์หัวข้อด้วย
- `visit` — เข้าเว็บ 1 ครั้งต่อ browser session (`sessionStorage` flag) ส่งจาก layout ฝั่งผู้ใช้
  ไม่นับหน้า `/admin` และ `/login`

**ที่เก็บ:** ตัวนับรายวัน key = `(day, kind, topicId)` (`topicId = ""` สำหรับ visit, day เป็นวันที่
เวลาไทย `YYYY-MM-DD`) เพิ่ม `StatsRepository` ใน `Repositories`:
```ts
interface StatsRepository {
  increment(e: { kind: "view" | "report" | "visit"; topicId: string; day: string }): Promise<void>;
  list(sinceDay: string | null): Promise<{ day: string; kind: string; topicId: string; count: number }[]>;
}
```
- file: คีย์ `usage` ใน `db.json` (เขียนผ่าน `serialized` เดิม)
- memory: map ในหน่วยความจำ
- supabase: migration `0006_usage.sql` ตาราง `usage_daily (day date, kind text, topic_id text,
  count int, primary key(day, kind, topic_id))` + ฟังก์ชัน `increment_usage(...)` (insert … on conflict
  do update count = count + 1) RLS เปิด, revoke จาก anon/authenticated เหมือนตารางอื่น
- sheets: แท็บ `usage_daily` + action `usage.increment` / `usage.list` ใน Apps Script (ทำใต้ lock เดิม)
  ต้อง deploy script ใหม่ — ระบุใน README
- failing: throw (ผู้เรียกกลืน error)

**บริการ:** `statsService()` — `record(event)` ไม่ throw (log error แล้วจบ), `getPublicViewCounts()`
(ยอดดูรวมทุกช่วงต่อหัวข้อ) แคชในหน่วยความจำ 60 วินาทีต่อ instance (sheets ช้า ~1 วินาทีต่อครั้ง),
`getAdminStats(range)` ไม่แคช อ่านไม่ได้ → คืนค่าว่าง/`degraded` หน้าเว็บยังทำงานปกติ

**ฝั่งผู้ใช้ (หน้าแรก):**
- `TopicMeta` ต่อท้าย "ดู N ครั้ง" (ไอคอนตา) เมื่อ N ≥ 5 — ตัวเลขน้อยกว่านี้ดูโหรงเหรง (การตัดสินใจของผู้สร้าง)
- ป้าย "ยอดนิยม" บน 5 หัวข้อที่ยอดดูสูงสุด (ต้อง ≥ 5)
- แถบ "ปัญหาที่พบบ่อย" แสดง 3 อันดับแรก เหนือรายการ เฉพาะตอนไม่ได้ค้นหาและไม่ได้เลือกหมวด
  กดแล้วเลือก/เปิดหัวข้อนั้น (และนับยอดดู) ไม่แสดงเลยถ้ายังไม่มีหัวข้อไหนถึง 5
- ลำดับรายการเดิมไม่เปลี่ยน

**ฝั่งเจ้าหน้าที่:** หน้าใหม่ `/admin/stats` (ทุกบทบาทของเจ้าหน้าที่เข้าได้) ปุ่ม "สถิติ" ในหน้า
จัดการเนื้อหาข้างปุ่ม "หมวดและระดับ" ช่วงเวลา 7 วัน / 30 วัน / ทั้งหมด (ค่าเริ่มต้น 30 วัน) แสดง:
จำนวนการเข้าเว็บ, ยอดดูรวม, ยอดแจ้งรวม (รวมที่ไม่ได้มาจากหัวข้อ) และตารางหัวข้อเรียงตามยอดดู —
ชื่อหัวข้อ, หมวด, ยอดดู, ยอดแจ้งปัญหา, สัดส่วนแจ้ง/ดู (%) — หัวข้อที่ถูกลบแล้วแสดงเป็น "(หัวข้อถูกลบ)"

## ข้อจำกัด / ความเป็นส่วนตัว

- ตัวนับไม่มีข้อมูลส่วนบุคคล; ข้อมูลผู้แจ้งยังไปที่ Sheet log เท่านั้นเหมือนเดิม
- `/api/log` คงการตรวจ same-origin, ขนาด body, และรับเฉพาะหัวข้อที่มีอยู่จริง
- ข้อความภาษาไทยทั้งหมดอยู่ใน `src/i18n/th.ts`
- ทดสอบ: unit ของ schema, repository แต่ละ backend (file/memory + mock fetch สำหรับ sheets),
  service (cache, degraded), component (thumbnail, ยอดดู, ป้าย, แถบยอดนิยม), route `/api/log`

## ปล่อยให้ผู้สร้างตัดสินใจ

ชื่อไฟล์/คอมโพเนนต์, สีและไอคอนของป้าย "ยอดนิยม", รายละเอียดการจัดวางที่จอแคบ
